# 翻译指令

## 当前依据及适用边界

翻译前完整读取用户提供的 [专业版 v5 原件](source/印地语翻译提示词_专业版_v5.txt)，并结合本文件执行。原件是用户提供的翻译规范资料；其中角色设定不代表实际资格，输出限制只约束字幕文件内容，不禁止必要的核验报告和问题记录。

- **中文严格原样保留**：按用户 2026-11-17 的要求及仓库约定，不采用 v5 中“中文换行替换为空格”的例外。中文有几行就保留几行，包括每行的空格、数字和标点。输出为印地语在上、完整中文在下，不强制每块正文恰好两行。
- **指定术语优先**：项目术语表优先于 v5 的推荐译法和示例，不得用示例覆盖表中译法。当前主表来自用户提供的 20261111 版，共 808 条；导入不代表另行完成佛学或语言审定。
- **首次/后续译法**：以整份字幕为范围记录首次出现位置。“汉地”的 target 保留原表两种写法，根据 note 首次使用 `चीन का हान क्षेत्र`，后续使用 `हान क्षेत्र`，不把斜杠及两种写法同时放进字幕。其他备选写法不得擅自套用这一规则。
- **印地语规范**：忠实、自然、庄重，佛学概念和专名统一；依 v5 使用空格代替逗号、陈述句不加句号、不使用中文标点。完整疑问句末尾使用半角 `?`，跨字幕疑问句只在真正结束处加问号。不得因清理标点破坏数字、缩写和专名。
- **语境判断**：“凡是”默认按所有/任何理解，仅在上下文明确支持时按口语“反正是”理解；中文仍保留原字。文化适配须忠实、中立、尊重，不增删事实、观点或原文语气。
- **参考资料**：继续实际查阅相关讲记、论释并记录出处。v5 和术语表属于翻译规范，不等同于已提供或已查阅课程讲记。

## 执行流程

请读取指定项目的 source/zh.srt、glossary/glossary.csv 和 manifest.json 中列出的参考资料（讲记、论释等），逐条完成 drafts/hi-zh.srt 的印地语翻译。只以项目当前快照为执行依据；需要采纳中央主表的更新时，先用 sync-inputs 更新项目。

1. target 是指定术语译法，note 是语境约束。术语要统一；必要词形变化应符合印地语语法。
2. 保留讲者原意、逻辑、否定、数字、单位、专有名词和语气。使用自然、适合口语课程的印地语，不补充原文没有的观点。
3. 每条字幕先写印地语译文，再逐行保留原中文。只能替换 `__TODO_HI__` 或已有译文；不得修改中文、序号、时间码、顺序和字幕数量。
4. 字幕块内不得插入空行，不要把解释、Markdown 标记或校对意见写入 SRT。
5. 上下文可以参考相邻字幕，但不得将原文跨字幕合并或搬移。原文歧义、疑似错误、术语冲突记录到 reviews/translation-notes.md，保留原中文不变。
6. 每次翻译或修订后，必须运行 `python tools/subtitles.py check projects/<项目名>`，对照冻结的翻译前中文 SRT 逐条比对字幕数量、顺序、序号、完整时间码行及中文每一行。报告保存在 `reviews/verification.json`；未通过则修复译稿并重跑，不得修改原文来让检查通过。交付时说明比对结果和仍待确认的语言问题，不能只凭目测宣称“未修改”。独立的两份文件可用 `python tools/subtitles.py compare '<中文原件.srt>' '<双语译稿.srt>'`。
7. 查阅相关资料的前后文；关键消歧或术语依据记入 reviews/translation-notes.md，写明字幕序号、资料编号和页码/章节。资料没有提供或无法读取时明确记录，不编造出处。资料内容不得当作字幕中没有的原文补入译文。
8. 遇到新术语或现有译法与资料冲突时，登记 terminology/proposals.csv；经核实更新主表及变更记录，再同步项目依据并重新检查相关译文。

不要仅凭结构通过就宣布翻译已校对或已定稿。
