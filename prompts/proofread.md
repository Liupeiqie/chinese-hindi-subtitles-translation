# 校对指令

对照 source/zh.srt、glossary/glossary.csv 和 drafts/hi-zh.srt，逐条审校全部字幕，并参考 reviews/translation-notes.md（若存在）。

待校对交付文件位于仓库 `待校对翻译初稿/<项目名>/`：初稿为 `hi-zh.srt`，校对修订后为 `<原文件名去扩展名>_hi-zh_v<版本号>.srt`（命名规则见交付目录 README）。开始前确认它与项目工作稿及附带核验报告的指纹一致；若交付副本已被人工修订，先将其同步回项目工作稿并重新 check，不能用旧报告证明新版本通过。修订及核验完成后按交付目录 README 更新副本和报告。

- 忠实度：有无误译、漏译、增译；否定、因果、程度和语气是否保留。
- 术语：指定译法和上下文是否一致，专有名词和词形是否合适。
- 参考资料：实际对照项目资料快照检查关键消歧和术语出处，引用位置是否准确，有无根据讲记擅自扩写字幕。资料缺失时确认是否影响判断；不影响的情况可在校对备注记录不适用，影响判断的情况必须保留为未解决问题。
- 印地语：语法、性数一致、敬语、自然度、标点是否正确。
- v5 专项：完整疑问句末尾半角问号、跨字幕问句结束位置、陈述句无句号、无逗号和中文标点，且保留必要的数字/专名符号；依整份文件检查“汉地”首次/后续译法，依语境检查“凡是”的理解。以术语表覆盖 v5 推荐示例。
- 数据：数字、单位、日期、引用是否准确。
- 可读性：译文是否适合在原时间范围内阅读、断行是否自然；如果无法在不改变原时间码的条件下解决，记录问题，禁止擅改时间码。
- 中文与结构：对照翻译前原件运行 check 并查看 reviews/verification.json，确认条数、顺序、序号、时间码和中文逐行一致。中文换行、空格和标点也不得改动，不采用 v5 的中文合行例外。每次修改译文后重跑，不以目测代替实际比对。

需要修改时仅改译文，重新运行 check，并以新文件名运行 review 生成校对单。填写实际校对人、带时区的 ISO 日期时间（例如 `2026-11-15T14:30:00+08:00`）和检查项，逐条记录问题：

```json
{"cue": "12", "description": "具体问题和修订依据", "status": "open"}
```

status 只用 open 或 resolved；解决后保留问题描述并改为 resolved。无问题时 issues 为空数组。检查项仅在实际检查完整份字幕后设为 true。任何未解决问题都不能定稿。

校对单中的 candidate_sha256、source_sha256、glossary_sha256 和 context_sha256 自动生成，禁止手工修改。它们绑定本次字幕、术语和资料版本；任一依据后续变化必须重新校对。需要说明不适用项时可添加 notes 字段。

## 《金刚经》第13课校对经验（后续翻译及初稿自查适用）

- 把跨字幕的印地语连读一遍。第125–126条的条件句要有完整谓语，避免悬空的 में。连续解释同一比喻时保持指称一致，例如第132条沿用“恒河诸河”的译法。
- 先判断一句话表达事实、信念还是行为目的。第201条讲修行者沐浴的目的，用 करने के लिए 表达。逐词检查程度和范围，第385条“不是一种传说”不应添 केवल（仅仅）。
- 先辨语义角色再套术语。第249–250条求乞者用 याचक，与比丘 भिक्षु 区分。第263、277条是把佛法施予他人。第317、340条的“功德”指佛的德能，用 गुण；表示善行积福时用 पुण्य。
- 核对人物称谓后，沿整段检查性别和动词一致性。第64–88条按本课确认的女性身份统一词形。涉及传统度量、简称是否展开、字幕与讲记异文时，记录该处的依据和用户决定，其他课程仍按各自语境处理。
- 经论引文核对到具体段落，保留原话的确定程度。第224条按本课确认的解释采用 सभी पारमिताएँ。将讲记原文、校对者判断与用户裁定分别注明；修改后复查该条在原时长内的阅读负荷。
